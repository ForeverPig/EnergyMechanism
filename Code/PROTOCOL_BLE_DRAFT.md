# ESP32 蓝牙与上位机通信规范草案

版本：Draft 0.2；日期：2026-11-07。适用：ESP32-C3、中心 STM32、Windows 上位机、Android/iOS 微信小程序。

**本文是待评审的接口草案，不是已实现功能说明。本次只更新文档，不修改、编译或烧录固件。** 用户确认的行为标为“已确认”；GATT、报文字段、命令编号和建议策略属于本稿技术提案，尚未冻结。未确认的运动策略不在本文擅自定值。

现状：ESP32 工程使用 ESP-IDF 5.4，只有与中心的 UART 查询测试；现有 STM32 V1 只有基础调试功能，电机驱动禁用。BLE、多端路由、正式训练和运动保护均不能因本文发布而视为已实现。现有帧格式仍以 [基础调试协议 V1](PROTOCOL_DEBUG_V1.md) 为准。

## 1. 已确认的产品边界

1. 基础击打检测、机关运转和必要故障保护优先；上位机、压力曲线、成绩展示不能阻塞它们。推进开符流程的有效击打判定本身仍是基础功能。
2. 中心 STM32 是模式、颜色、方向、阶段、目标叶片、有效击打、成功/失败和重开倒计时的唯一判定者。ESP32 管理连接和转发；界面显示中心确认的状态。
3. 五块叶片共用固件和 CAN ID；中心按物理 CAN1～5 编号，不需要逐片编号烧录。CAN1 同时接 C620。
4. 自由训练支持大符/小符、红/蓝；不做比赛机会时间轴和独立电机调试模式。
5. 随机方向开启：每次新开符随机一次，连续自动重开也重新随机；同一尝试中不因 UI 刷新或请求重试重新抽取。运行中修改随机开关或固定方向，本轮方向不变，下一次新开符（含连续自动重开、手动重新开启）采用新设置；需要反向时先由中心完成运动过渡。关闭随机：选择固定顺时针或逆时针。方向统一按**面对叶片击打面**观察。
6. 连续自动重开保留；成功或 20 秒尝试超时后，等待设置的间隔再开同类型、同颜色的符。间隔默认 3 秒，可选 1～30 秒，步进 1 秒。成功增益只作一句提示，不执行增益保持倒计时。
7. 运行中大小符或颜色切换被中心接受后，立即结束旧尝试并切换；旧尝试标为切换中断。立即切换业务状态不等于电机可以瞬间反向或跳速。
8. 返回首页不停止运行；运行页设明确停止按钮。蓝牙断开不影响当前流程，包括连续开符。
9. 进入调试须提示会停止大小符，经用户确认后停轮停转。重新校准只允许在已经确认停转的击打测试模式。退出调试后保持停转待机，需用户再次点击“开启能量机关”才运行。
10. 任一叶片失联，中心停止本轮并停转；不能把故障当成普通 20 秒失败自动重开。
11. 全部控制端共享一个当前观察叶片。最后一个压力观察者退出后关闭压力流；采样、击打检测和心跳继续。
12. 本版只展示当轮情况和成绩，**暂不加入历史成绩累计、历史列表、成功率趋势或跨平台历史同步**。有限 RAM 事件缓存用于重传、去重和重连修复显示，不是历史成绩功能。

## 2. 界面结构与通信动作

```text
一级：首页
├─ 连接/状态栏：设备、连接状态、中心状态、可用的基础遥测
├─ 1 设置栏
│  ├─ 红 / 蓝
│  ├─ 大符 / 小符
│  ├─ 随机旋转方向开关
│  ├─ 固定方向：顺时针 / 逆时针（随机关闭时可选）
│  ├─ 连续自动重开开关
│  └─ 连续自动重开间隔：默认3秒，1～30秒，步进1秒
├─ 2 开启能量机关 → 二级：运行页
│  ├─ 当前大符/小符、颜色、实际方向
│  ├─ 中心确认的阶段、目标叶片、当轮击打和成绩
│  ├─ 成功/失败/中断原因、重开倒计时、单句增益提示
│  ├─ 停止按钮
│  └─ 返回首页（继续运行）
└─ 3 调试 → 确认弹窗 → 二级：调试总览
   ├─ 五块叶片基础信息
   └─ 选择一片 → 压力测试子界面
      ├─ 十路 raw / baseline / delta / peak / state
      ├─ 约 20 Hz 曲线、近期测试击打
      ├─ 重新校准及校准状态
      └─ 返回总览（退出本连接的压力观察）
```

压力测试是调试总览中的子界面，不在首页增加平级菜单。基础遥测按设备能力显示；未实现电压不能显示成 0 V，尚未确认传动比时不能把转子 rpm 当作机关 rpm。

| 操作 | 发出的业务请求 | 中心/网关处理与界面反馈 |
| --- | --- | --- |
| 连接设备 | HELLO、GET_STATE、GET_LEAVES，订阅结果/状态/事件 | 先获取当前状态，不自动开符、不默认设备处于待机 |
| 改设置 | PATCH_SETTINGS，只带本次改变的字段 | 显示提交中；成功后以中心回读为准，失败还原并显示原因 |
| 点击开启 | START，带已确认的设置版本 | 可先打开运行页显示启动中；收到中心运行状态后才能显示运行中 |
| 已有另一端启动，点击进入运行页 | GET_STATE | 进入当前运行显示；不得为打开页面额外结束或重开一轮 |
| 运行页返回 | 无停止请求；保留基础状态订阅 | 返回首页，显示设备仍在运行 |
| 点击停止 | STOP | 先显示停止中，中心确认实际停转后显示已停止；同时取消当前自动重开流程 |
| 点击调试 | 暂不发请求，先显示确认弹窗 | 弹窗文案建议：“进入调试模式将停止当前大小符及连续自动重开，是否继续？” |
| 确认调试 | ENTER_DEBUG | 等待中心结束尝试、停转并进入 HIT_TEST；仅收到接受应答还不能校准 |
| 取消弹窗 | 无请求 | 当前训练继续 |
| 选择叶片 | OBSERVE_ENTER(slot) | 加入观察并请求全局选择；所有观察端跟随获准的新叶片 |
| 压力页正常退出 | OBSERVE_LEAVE | 只移除本连接；仍有其他观察者则保持压力流 |
| 小程序进入后台/页面不可见 | 尽力取消观察，并停止续租 | 异常未送达由租约到期兜底；不改变训练运行 |
| 重新校准 | CALIBRATE(slot) | 中心检查 HIT_TEST、已停转、叶片在线；分别显示接受、进行中、READY/不稳定/失败 |

**已确认：** 退出调试后进入停转待机，不自动恢复之前的训练，需再次明确点击“开启能量机关”才运行。对应业务命令为 EXIT_DEBUG；仅页面返回也不得隐式启动。

**建议待评审：** 其他控制者启动训练时，测试页面立即变为只读并退出压力观察，显示“设备已由其他控制端启动”。

### 2.1 设置的生效时机

| 设置 | 已确认或本稿建议 |
| --- | --- |
| 颜色、大小符 | 已确认：运行期间接受后立即中断旧尝试并切换；待机修改只更新设置，不隐式启动 |
| 随机开关、固定方向 | 已确认：本次尝试保持原方向；下一次新开符，包括连续自动重开和手动重新开启，应用新设置；需要反向时先由中心完成运动过渡。界面同时显示“设置方向”和“本轮实际方向” |
| 连续开关关闭 | 建议：完成当前尝试后不再重开；若正在重开等待，则取消这次自动重开，运动如何收尾按待定停止策略执行 |
| 连续开关开启 | 建议：当前尝试结束后进入连续流程；在停转待机修改开关不直接启动 |
| 重开间隔 | 建议：新值用于下一次进入等待；已经进行的倒计时保持原截止时刻，避免多端修改导致倒计时跳变 |

连续开关与间隔在运行中修改的生效时机仍是建议，尚未确认。间隔取值已确认：默认 3 秒、范围 1～30 秒、步进 1 秒；协议字段采用毫秒，即默认 3000、允许 1000～30000 且为 1000 的整数倍，界面按秒展示。非法值返回 BAD_ARGUMENT，不静默截断或改变用户选择。

“下一次新开符”是指生成新 attempt_id 的下一次尝试，包含连续自动重开；不要求先点击停止再手动启动。例如本轮从“随机”改成“固定顺时针”，本轮保持原方向，自动重开时采用顺时针。方向切换的具体减速/停转/再加速参数，以及单次结束/等待期的运动策略仍待硬件确认。

## 3. 基础功能优先的执行约束

| 优先层次 | 工作 | 不能依赖的条件 |
| --- | --- | --- |
| 实时基础 | ADC/DMA、击打算法、电机反馈与控制、必要保护 | BLE 是否在线、手机是否确认、曲线是否绘制完 |
| 运行通信 | 击打可靠传递与去重、心跳/故障、目标/阶段切换和必要灯指示 | 成绩落盘、事件回放、慢客户端发送完成 |
| 有界控制 | 控制请求裁决、停止、模式切换、执行结果、状态同步 | 大量普通请求或压力流占满全部处理资源 |
| 可降级显示 | 压力快照、扩展遥测、成绩展示、重连补取、日志 | 不得反过来阻塞前三层 |

- 叶片检测完成后把事件放入专用有界队列，不在 ADC/检测路径等待 CAN 重发；中心先去重及运行判定，再异步向 ESP32 输出结果。
- CAN、UART、ESP32 各连接都要有固定队列和每次调度处理量上限；控制/事件与压力/日志分开预算。分特征值只是分类，不能代替实际 CPU、队列和无线发送预算。
- 压力保留最新快照，慢端可降频、跳过旧数据；状态快照可合并；控制请求超出预算返回 BUSY/RATE_LIMIT。不要无限排队到几秒后执行过时启动命令。
- 已接收且有效的 STOP 和真实保护动作优先处理；建议 STOP 绕过普通操作死区，但仍检查会话和设备启动标识，不能接受旧设备会话中的停止包。
- BLE 全断、ESP32 重启或 UART 显示链路中断只造成控制/显示暂不可用、压力租约失效；既有中心训练流程继续。真实叶片失联仍必须停轮停转。
- 基础击打队列溢出、采样异常等不能静默丢弃后声称正常；必须报告。除已确认的叶片失联策略外，其他故障的具体停机/恢复动作需硬件验证后定版。
- 不在基础路径中格式化大段 JSON、同步写日志、等待蓝牙发送或擦写 Flash。本文不引入成绩 Flash 保存；蓝牙栈初始化/配对存储与用户参数保存是不同事项。

## 4. BLE 服务草案

### 4.1 角色与兼容性

ESP32 作为 BLE 外设/GATT 服务端；Windows 和微信小程序作为 GATT 客户端。本稿建议使用现有 ESP-IDF 5.4 对应的 NimBLE 路线；官方文档确认该版本支持 ESP32-C3 的 NimBLE 主机集成，具体并发数与资源配置仍需在本板上验证。[Espressif 文档](https://docs.espressif.com/projects/esp-idf/en/v5.4/esp32c3/api-reference/bluetooth/nimble/index.html)

Windows 接口采用服务发现、特征值读写和通知订阅模型；最终 UI 框架暂不锁定。应用必须定义自己的业务应答，GATT 写入成功本身不表示中心已完成动作。[Microsoft GATT 客户端文档](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/gatt-client)

微信实现时再核对当前基础库的扫描、连接、写入、通知、后台行为及 Android/iOS 差异。本文采用保守的小分片设计，不假定平台允许固定的大 MTU；此处不宣称已完成微信真机兼容性验证。

广播名建议 `EnergyMechanism-XXXX`，仅作方便识别；设备身份以握手返回的稳定 device_id 为准，不依赖手机暴露的地址格式。最大连接数通过能力返回，不能默认无限多端。配对/连接许可与允许哪些人控制尚未确定，不将“任何靠近者都可控制”作为既定策略。

### 4.2 GATT 表（UUID 为本稿提案）

自定义 Service：`af510000-7b3d-4b28-9f02-6c6d454d0001`。下表 UUID 以同一后缀 `-7b3d-4b28-9f02-6c6d454d0001` 补齐。

| UUID 前段 | 名称 | 属性 | 数据 |
| --- | --- | --- | --- |
| `af510001` | INFO | Read | 16 字节基本版本信息，无分片 |
| `af510002` | COMMAND | Write with response | 客户端命令分片 |
| `af510003` | CONTROL | Notify | 握手、命令结果、中心状态、叶片信息 |
| `af510004` | EVENT | Notify | 已判定击打、当轮结果、故障/事件补取 |
| `af510005` | PRESSURE | Notify | 当前选中叶片的完整压力快照分片 |

SESSION_INFO 建议返回 device_id、gateway_epoch、client_session、center_boot、三端固件/协议版本、中心链路状态、最大连接数、载荷上限，以及能力位：状态读取、大小符控制、运动控制、压力观察、校准、电压、阈值修改、参数保存。能力必须反映实际固件；未实现的运动/阈值/Flash功能保持关闭。中心离线时可完成ESP会话握手，但修改机关状态的命令返回LINK_DOWN，不能把缓存状态当成实时状态。

INFO 建议布局：`magic[4]="EMB2", major u8=2, minor u8=0, max_frame u16, max_clients u8, flags u8, reserved u16=0, capability_revision u32`，共 16 字节。flags 初拟 bit0=中心在线、bit1=业务协议就绪；其余保留为 0。详细能力通过 HELLO 获取。

客户端先订阅 CONTROL/EVENT 再发 HELLO。仅打开 PRESSURE 的通知开关不算业务观察者；必须发送 OBSERVE_ENTER，避免停留在后台的通知订阅永久开启采样快照流。

COMMAND 使用逐片有应答写入，客户端限制在途写入；不把平台写成功当作业务成功。CONTROL/EVENT 使用业务请求号、事件号及有限重试处理丢失，中心不等待手机通知确认。

### 4.3 BLE 分片

本稿建议初版每次特征值写入/通知最多 **20 字节**，这是工程基线，不是宣称所有平台最大只能发 20 字节。更大分片后续通过能力协商启用。

| 字段 | 长度 | 规则 |
| --- | --- | --- |
| transfer_id | u16 | 单连接、单特征值内的传输编号，与命令请求号和事件号无关 |
| fragment_index | u8 | 从 0 开始 |
| fragment_count | u8 | 整包分片数，初版 1～13 |
| fragment_data | 1～16 字节 | 除末片外固定 16 字节；顺序拼接成一条完整业务帧 |

按“连接会话＋特征值”分别重组，每组最多一条未完成消息。缺片、越界、编号冲突、超长、超时均丢弃未完成消息并计数；不得把半包交给业务逻辑。重传采用新的 transfer_id 发送整条帧，业务 request_seq/event_id 保持原值。传输编号不能在旧残片仍可能存活时复用。

同一特征值的消息分片不能交织；不同特征值之间允许调度优先级不同。压力旧包未送完时可废弃，接收端遇新 transfer_id 丢弃旧未完成包；CONTROL/EVENT 的中途放弃必须保留待重试或明确缺口信息。

重组超时、队列上限均为第 12 节待实测参数。BLE 分片不使用 UART 的字节间超时，不能直接把现有 UART 的 100 ms 套到手机通知间隔。

### 4.4 完整业务帧（拟议 V2）

复用现有帧外壳，**版本改为 2，载荷含义另行定义**；不能把下述命令发给现有 V1 并期望可执行。

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 2 | `A5 5A` |
| 2 | 1 | version=2 |
| 3 | 1 | type |
| 4 | 2 | payload_len=N，BLE 初稿 N≤184 |
| 6 | 2 | request_seq；请求及其应答为同一非零值，异步消息为 0 |
| 8 | N | payload |
| 8+N | 2 | CRC16/CCITT-FALSE，小端；覆盖从 version 开始的 6+N 字节 |

所有多字节字段小端；CRC 参数沿用 V1：poly=0x1021，init=0xFFFF，不反射，xorout=0。完整 BLE 业务帧最多 194 字节，按 16 字节数据分片最多 13 片。CRC 用于检出组包/转发错误，不承担访问认证。

消息类型提案：`0x01 REQUEST`、`0x02 RESULT`、`0x03 SESSION_INFO`、`0x10 STATE`、`0x11 LEAF_INFO`、`0x12 PRESSURE`、`0x13 HIT`、`0x14 MOTOR`、`0x15 ATTEMPT_RESULT`、`0x16 FAULT`、`0x17 REPLAY_END`。V2 与 V1 的同值 type 不保证同载荷结构，必须先检查版本。

## 5. 业务命令与执行结果

本节确定候选字段及语义；除明确列出固定布局的内容外，详细偏移/结构长度在协议评审后冻结。不要据本稿直接强转 C struct；正式实现需显式序列化并提供逐字节测试向量。

### 5.1 请求

REQUEST 载荷提案：`opcode u8, expected_center_boot u64, expected_control_revision u32, args[]`。

只读/握手请求可将两个 expected 字段置 0；改变设备状态的命令必须携带最新中心启动标识。control_revision 只在影响控制条件的设置、启停、模式转换、故障等变化时递增，压力、心跳和普通击打不能每次都令用户命令过期。具体哪些自动阶段变更影响控制条件需在状态机实现中列明。

| opcode | 请求 | args 候选 | 语义 |
| --- | --- | --- | --- |
| `0x01` | HELLO | client_kind u8、支持版本范围 | ESP 返回会话、设备身份、能力和中心是否就绪；不能触发运动 |
| `0x02` | GET_STATE | 无 | 当前全量状态与当轮摘要 |
| `0x03` | GET_LEAVES | slot u8；0=全部 | 五片分消息返回，带同一批次标识，不能把五片塞进一个超长包 |
| `0x10` | PATCH_SETTINGS | field_mask u16＋对应字段 | 中心一次校验后原子应用，不发送未改的旧设置覆盖其他人 |
| `0x11` | START | settings_revision u32 | 用中心已确认的设置开符；建议已运行时返回 ALREADY_RUNNING，不隐式重开 |
| `0x12` | STOP | 无 | 结束当前尝试、取消当前连续流程并停转；建议幂等，不因重试再产生中断 |
| `0x13` | ENTER_DEBUG | 无 | 停轮停转后进入 HIT_TEST；不自动订阅压力 |
| `0x14` | EXIT_DEBUG | 无 | 已确认退出到停转待机；后续启动须明确 START |
| `0x20` | OBSERVE_ENTER | slot u8=1～5 | 加入压力观察，并请求全局选择该片；仅 HIT_TEST 中允许 |
| `0x21` | OBSERVE_RENEW | observer_token u32 | 续订本连接观察，不带叶片号，避免旧观察者反复把全局选择切回去 |
| `0x22` | OBSERVE_LEAVE | observer_token u32 | 退出本连接观察；重复退出幂等 |
| `0x23` | CALIBRATE | slot u8=1～5 | 已停转的 HIT_TEST 中重新校准指定叶片 |
| `0x30` | EVENT_ACK | center_boot u64、event_cursor u32 | 本连接已连续收到的事件游标；不作为中心运行的前提 |
| `0x31` | REPLAY_CURRENT | center_boot u64、attempt_id u32、after_cursor u32、limit u8 | 有界补取当前尝试事件；不可查询长期历史 |
| `0x32` | QUERY_REQUEST | original_request_seq u16 | 查询本会话某请求的既有执行结果，不重新执行 |

PATCH_SETTINGS 字段提案：bit0=`color u8`（0红/1蓝）；bit1=`rune_kind u8`（0小/1大）；bit2=`direction_policy u8`（0固定/1每次随机）；bit3=`fixed_direction u8`（0顺时针/1逆时针，面对击打面）；bit4=`auto_restart u8`（0/1）；bit5=`restart_delay_ms u32`。按 bit 从低到高编码，保留 bit 必须为 0。restart_delay_ms 默认 3000，合法值为 1000、2000、…、30000。关闭随机时必须已有有效固定方向；不通过隐式默认方向绕过用户选择。

### 5.2 结果

RESULT 建议字段：`opcode, phase, result_code, center_boot, control_revision, attempt_id, operation_id`，可附本命令需要的固定扩展，如 observer_token、当前设置版本。错误显示由客户端按错误码生成，不依赖中心发送中文长字符串。

| phase | 意义 |
| --- | --- |
| ACCEPTED | 请求已验证并开始处理；不等于电机已停或校准已完成 |
| COMPLETED | 对应业务完成；STOP=实际停止确认，ENTER_DEBUG=进入停转 HIT_TEST，CALIBRATE=完成并报告校准结果 |
| REJECTED | 未执行：参数、模式、版本、资源、前置条件等不满足 |
| FAILED | 已接受的操作执行失败，给出原因与实际状态 |
| UNKNOWN | 网关未能确认最终结果；不能宣称动作没有发生 |

候选错误码：OK、BAD_ARGUMENT、UNSUPPORTED、NOT_READY、WRONG_MODE、NOT_STOPPED、LEAF_OFFLINE、BUSY、RATE_LIMIT、STALE_STATE、ALREADY_RUNNING、TIMEOUT、LINK_DOWN、REQUEST_CONFLICT、REPLAY_EXPIRED、CACHE_GAP、FAULT_ACTIVE。数值表待冻结。

请求结果定向发给发起端；统一状态向所有订阅端广播。STOP/校准等后续阶段继续使用原 request_seq 和 operation_id。客户端丢失结果时先用同号同内容重试或查询，不能用新号反复 START。

应答收尾规则提案：HELLO以单条SESSION_INFO完成，GET_STATE以单条STATE完成；GET_LEAVES各条数据带同一批次号和条目数，最后用RESULT(COMPLETED)收尾。修改命令可直接完成，或先ACCEPTED再报告最终结果。REPLAY_CURRENT用同一非零request_seq定向返回重放事件，以REPLAY_END收尾；正常实时事件才使用seq=0广播。ESP映射在最终收尾前必须保留，不能在收到ACCEPTED或第一片数据时释放。超时只能标记结果未确认，迟到终态仍按会话与请求身份处理。

## 6. 多端映射、重试与并发操作

### 6.1 请求身份与映射

已确认 ESP32 保存：`(gateway_epoch, uart_seq) → (client_session, client_request_seq, opcode, 请求内容摘要, 处理状态)`。叶片无需知道连接者是谁。A 和 B 都可使用自己的 request_seq=1，ESP 分配不同 uart_seq，回包才不会发错人。

技术提案：每次客户端连接/业务会话获得新 client_session；ESP32 每次启动获得新 gateway_epoch；中心重启有新 center_boot。使用 64 位标识作为候选，但启动标识生成办法须结合硬件确认，不能把恒定 UID 或清零后的 uptime 当作启动代次。

- 同一客户端会话内请求号非零、递增且不复用。16 位耗尽前停止新增请求、处理在途项并重新握手建立业务会话；不能直接回绕到 1。
- 同号同内容重试返回既有状态/结果；同号不同内容返回 REQUEST_CONFLICT。超过结果缓存保留期的旧请求只返回 REPLAY_EXPIRED，不再次执行；实现需保存有界重放窗口或高水位。
- 客户端断开后，未下发的运动请求取消；已经被中心接受的动作不会因断开撤销。迟到结果不能发给复用了同一 BLE 连接句柄的新连接。
- ESP32 重启后不能猜测旧请求有没有执行，更不能恢复队列自动重发 START；先重建网关会话、读取中心当前状态。
- 多端请求由中心按确定顺序裁决。建议使用 expected_control_revision 拒绝过期修改，返回最新状态让用户重新操作；普通操作死区长度待定。没有永久“主控端”；访问许可方式尚待确定，状态门禁与资源限制对所有控制端一致适用。

### 6.2 UART 的必要升级边界

现有 V1 的 3 字节 `[opcode, port, value]` 无法表达这些命令；现有 ESP32 测试程序也不是 BLE 透传固件。

建议 UART V2 保留现有 192 字节载荷上限、1 Mbps/8N1 与 CRC 外壳。请求以及非零 seq 的定向应答在 BLE 载荷前增加 `gateway_epoch u64`，故 BLE 载荷上限预留为 184 字节；ESP 去掉/补入此字段并转换请求号。异步 UART 状态、事件使用 seq=0，通过载荷中的 center_boot/事件身份区分来源。

中心只接受已握手网关代次的修改请求，拒绝旧代次残留包；所有定向应答回显代次和 uart_seq。uart_seq 同样不得在同一代次中复用，耗尽时须在在途项收尾后更新网关代次。握手换代不触发停转、启动或重置训练。

网关会话更换、未决请求结果、序号重放窗口需一起验证，不能只在 ESP 连接表里保存一个易复用的数字。当前 V1 解析器/命令分派不修改，V2 只有升级并完成能力握手后才能启用。

## 7. 状态、成绩与诊断数据

### 7.1 状态模型

顶层候选：`IDLE / STARTING / TRAINING / RESTART_WAIT / STOPPING / HIT_TEST / FAULT`。上位机不根据自己的倒计时推进状态；倒计时显示可在两次中心更新之间插值，过期后显示同步中而非自行宣告成功或失败。

每次新开符生成 attempt_id。连续重开、运行中颜色/大小符切换后的新尝试使用新 ID；大符内部第几组/第几靶用 stage/group 字段表达，不把一组误认为新尝试。

STATE 至少包括：

| 字段组 | 候选字段/解释 |
| --- | --- |
| 身份与版本 | center_boot u64、state_revision u32、control_revision u32、settings_revision u32、center_time_ms u32、快照对应的event_cursor u32 |
| 模式 | top_state u8、rune_kind u8、color u8、actual_direction u8、设置方向策略与固定方向 |
| 尝试 | attempt_id u32、stage_code u16、group_index u8、group_total u8、target_mask u8、hit_mask u8 |
| 时间 | attempt_elapsed_ms u32、phase_remaining_ms u32、restart_remaining_ms u32；未适用需有效位 |
| 连续设置 | auto_restart u8、restart_delay_ms u32、是否已安排下一次重开 |
| 当前成绩 | 有效命中数、当轮环数摘要、最后命中叶片/环数、结果/中断原因、增益摘要码 |
| 基础状态 | 五片在线/就绪 mask、电机反馈有效/停转确认、故障码、全局压力选择及选择代次 |

具体 stage_code 应由中心规则状态机统一枚举，例如首击等待、补击等待、换组、成功、尝试超时等；UI 不硬编码规则时间窗或自行判断“打中了就进下一组”。精确计分口径、有效环数策略继续引用现有规则大纲中的待定项，不能由 BLE 草案另造规则。

不同消息组成的初始快照须有相同 center_boot 和 snapshot_revision；期间的新状态只向更新版本推进，不能让迟到快照把界面回滚。32 位计时/序号回绕必须规定模运算或换代处理，不能用普通大小比较跨回绕判新旧。

### 7.2 当轮击打与成绩

HIT 候选字段：center_boot、center_event_seq、attempt_id、运行上下文、slot、leaf_uid、leaf_boot、leaf_event_seq、中心首次接收时间、叶片样本时间、环数、峰值、判定结果/无效原因、判定后的阶段版本。

ATTEMPT_RESULT 候选字段：center_boot、center_event_seq、attempt_id、符类型、颜色、实际方向、成功/20秒超时/手动停止/切换中断/故障中断、耗时、有效命中数、环数摘要、增益摘要、数据完整性标志。摘要数值的精确统计口径待规则层定版。

- 一次真实事件可能重复递送，显示也要按事件身份去重；同环同峰值的两次独立检测事件不能合并。
- 当轮成绩以中心结果为准，手机不能因少收一条消息自行推断本轮失败。硬件看不到完全打空的弹丸，不显示没有依据的“射击命中率”。
- 新尝试开始更新当前轮面板；前一轮成功可显示短暂增益提示，不增加历史累计。测试页近期击打列表和压力曲线均为有界临时显示。
- 中心短期缓存可跨越少量边界以完成可靠递送，但本版补取接口只服务当前尝试及正在送达的结束结果，不开放按日期/累计轮数查询。

### 7.3 叶片基础信息与压力

调试总览每片显示：slot、在线状态、UID/身份是否有效、启动代次、心跳年龄、校准状态、采样故障、ADC/DMA/CAN 错误或丢包计数；能力支持时再显示 VIN/5V。总览可低频刷新，故障变化及时通知，不默认拉取五片压力。

PRESSURE 候选布局：`center_boot u64, selection_epoch u32, slot u8, snapshot_seq u32, center_rx_ms u32, leaf_sample_ms u32`，随后十个记录，每个为 `ring u8, state u8, raw u16, baseline u16, delta i16, peak u16`，共 125 字节，符合 184 字节上限。

约 20 Hz 是观察目标，不是 ADC 采样率或击打检测频率。快照先在中心完整组装；丢一片或跨采样时间就丢该快照。raw/baseline/delta/peak 用 ADC 计数，未校准成牛顿前不标 N。

环号沿用当前硬件/检测映射：通道 0～9 对应 `6、7、8、9、10、5、4、3、1、2`。界面按 ring 显示，不把数组下标当环数。压力只得到环号，不能伪造沿圆周的精确命中位置。

MOTOR 显示 C620 的转子 rpm、原始电流、温度、反馈年龄和驱动状态；如后续支持机关轴估算转速，应另带换算有效标志与传动参数版本。当前电压未实现，UI 显示“未实现/无数据”，不伪造测量值。

## 8. 压力观察租约

1. 连接成功不自动成为观察者；只有可见的压力测试页发送 OBSERVE_ENTER。
2. ESP 为连接生成 observer_token；中心确认全局 slot 和 selection_epoch 后开始快照。若一人切到 4 号，其他观察者均显示 4 号并提示全局对象已改变。
3. 每个前台观察连接定期续租，只续 observer_token，不携带旧 slot。关闭页面、切后台、取消 PRESSURE 通知或断开连接都结束该端观察；异常退出按到期清理。
4. ESP 只要还有有效观察者，才向中心续订一个汇总租约；中心仍以 HIT_TEST 和合法叶片为门禁。ESP 重启/UART 断开后，上游租约必须到期。
5. 中心汇总租约有效时才刷新叶片压力租约。最后一个观察者退出后主动停止，租约到期作为兜底；中心不能自行无限续约。
6. 租约关闭不改变 ADC/检测/击打事件/心跳，不主动停止训练。进入训练则关闭调试观察，撤销全部旧 token；回到调试须重新加入。
7. 切换叶片、所选叶片重启/更换或重新建立观察时更新selection_epoch并清空旧未完成快照；客户端同时核验 center_boot、selection_epoch、slot，只显示当前对象数据。PRESSURE中的snapshot_seq由中心在该选择代次内生成，不直接把叶片V1的8位序号当成跨重启的唯一标识。

客户端租约、ESP→中心租约与中心→叶片租约是三层不同机制。现有末层 500 ms 续约/1500 ms 超时只描述 V1 现状，不自动确定前两层数值。

## 9. 击打可靠性与重连

### 9.1 叶片到中心

事件身份建议为“叶片 UID＋启动代次＋事件序号”，同时带当前运行上下文。中心保存第一次完整有效接收时间和判定结果；重复包只重发确认，不重新计分或推进状态。

本稿建议把叶片应用 ACK 明确定义为：**中心已经完成该事件的去重和一次运行判定，并记住重发时所需的处理结果**。ACK 不等待 ESP、手机或成绩存储。此为待评审的明确语义，当前 V1 尚未实现。

有限重发超过预算或基础队列满时必须报告，不承诺无限离线仍不丢事件。应用确认针对完整事件；CAN 控制器的链路确认不能代替中心业务确认。

时间窗采用中心首次完整接收时刻，重发不更新。切换前的迟到事件不能仅凭“刚收到”算进新尝试：正式 CAN 事件需携带中心下发的运行上下文代次，并设计激活/切换握手；新靶面开启前中心要确认所需叶片已经应用新上下文。其经典 CAN 分帧布局与超时属于后续 CAN 升级工作，不能省略。

### 9.2 中心到控制端

中心生成递增事件游标，ESP 给每个订阅端维护独立进度。一个端很慢或不确认，只影响它自己的事件递送/补取，不拖住其他端和中心实时逻辑。

EVENT_ACK 只确认该客户端在当前事件流基线之后连续收到的游标；有缺口不能越过缺口确认。重连先取全量状态和当前流基线，再有界补取缺失的当前尝试事件；重放消息带 replay 标志，不再次执行开符逻辑，也不重新弹出已展示的成功提示。

缓存超限/过期返回 CACHE_GAP 和可用范围，界面标记详细击打记录不完整并重新同步当前摘要。丢失 UI 事件不能变成一次新的检测事件，也不能触发停机。中心重启则旧 center_boot 的缓存、游标和请求全部失效。

## 10. 典型交互顺序

### 10.1 启动并连续重开

```text
客户端                  ESP32                      中心 STM32
HELLO / GET_STATE  →    建立会话、查询中心       →   返回当前状态/能力
PATCH_SETTINGS     →    分配 UART 序号          →   校验并应用
                   ←    定向结果＋广播状态      ←   确认设置版本
START(设置版本)    →    路由                    →   检查就绪、生成新尝试
                   ←    ACCEPTED / STATE        ←   准备、运动过渡
                   ←    STATE(TRAINING)         ←   进入有效运行阶段
HIT / 当轮状态     ←    广播并各端独立流控      ←   中心已完成击打判定
结果/重开倒计时    ←    广播                    ←   成功或20秒超时
新尝试/新方向      ←    广播                    ←   间隔结束，按设置再次抽方向
```

该过程中客户端退出、回首页或蓝牙全断不取消连续流程。随机抽样发生在中心为新尝试选方向时，请求重传不再抽一次。

### 10.2 调试及压力退出

```text
点击调试 → 本地确认弹窗 → ENTER_DEBUG
中心结束旧尝试 → 停转过渡 → 确认停止 → HIT_TEST
客户端进入总览 → 选择3号 → OBSERVE_ENTER(3)
ESP登记观察者 → 中心确认全局3号/新代次 → 下发压力订阅
3号快照 → 中心完整组包 → ESP按连接带宽发送 → 客户端曲线
返回总览 → OBSERVE_LEAVE
尚有其他观察者：继续；最后一人退出：关闭汇总租约及叶片压力流
```

如果停转未完成或反馈不可用，返回明确状态/失败原因，校准按钮不可用；不得为了进入页面而假定已经停止。

## 11. 实施顺序与兼容

1. 评审本草案的产品行为与命令语义，补齐第 12 节；保留版本/能力协商，不先冻结所有调试数值。
2. 基础检测与中心运动/保护按硬件验收推进；补齐可靠 CAN 事件、运行上下文、UART 会话及控制状态接口。
3. ESP 实现最小 BLE：握手、只读状态、定向应答、分片和压力租约；先做 Windows 命令行/协议模拟器联调，不以正式 UI 为前置条件。
4. 接入已验收的启停/调试命令，再做多端、慢端、断线、丢包、压力负载和故障注入测试。
5. Windows 与微信依据同一份版本化协议开发界面；可用模拟消息并行开发，实机以能力开关禁用未实现功能。协议变更同步更新示例与解析测试，不能让 UI 猜测 ESP 临时输出。

因此开发关系是“先规范接口、再逐层实现与联调”，并非等 ESP 全部写完后才从代码反推上位机。V1 基础工具可继续使用原格式；新增正式能力必须显式升级，未知功能返回 UNSUPPORTED。

本次没有验证真实 BLE 性能、手机兼容性或整机运行。现有 CAN/UART 测试通过仅证明对应基础链路，不是本规范的验收结论。

### 12.3 必须覆盖的验收场景

| 场景 | 预期 |
| --- | --- |
| 无控制端、断蓝牙、ESP重启 | 已有训练继续；压力租约最终到期，中心不等待界面 |
| 五片运行＋压力20Hz＋多端请求/慢端 | 基础时序达标；可降级遥测，队列有界，故障可见 |
| 叶片失联 | 停轮停转，无普通连续重开；客户端显示明确故障 |
| 重发START/切换、两端相同请求号 | 同一请求只执行一次，结果回正确会话 |
| 连接句柄复用、ESP/中心重启、序号耗尽 | 旧应答不串端，旧命令不自动重放，重新同步状态 |
| 训练时校准、停转未完成时校准 | 拒绝；接受校准后分别报告进行中与最终状态 |
| 最后观察者正常退出/异常退出 | 在规定上界内停流；其他人仍观察时不误停 |
| 两人反复切观察叶片、旧快照迟到 | 所有人显示同一获准对象，不串片、不混快照 |
| ACK丢失、重复事件、同环同峰值两次真击打 | 同事件不重复判定，两独立事件不误合并 |
| 模式/颜色切换边界、旧轮事件迟到 | 旧事件不计入新尝试；各端同步新状态 |
| 压力/通知拥塞、事件缓存耗尽 | 允许显示缺口，不阻塞检测/运转，不伪造完整记录 |
| 页面返回、启动/调试确认、显式停止 | 返回继续；取消调试不改变运行；完成应答符合实际状态 |
| 随机/固定方向及连续重开 | 面对击打面解释一致；运行中改方向只在下一新尝试生效，含自动重开；反向先完成运动过渡 |
| 重开间隔和退出调试 | 默认3秒、1～30秒/步进1秒；非法值拒绝；退出调试后不自动启动 |
| Windows、Android微信、iOS微信 | 分片/订阅/后台/重连分别实测，公布实际支持范围 |
