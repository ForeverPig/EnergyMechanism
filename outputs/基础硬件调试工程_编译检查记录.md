日期：2026-11-06。

本次按用户确认范围完成两套STM32工程：电机仅接收C620反馈；暂定调试协议实现叶片心跳、UID、击打事件、指定叶片压力快照、重新校准；保留4/4/2压力扫描。电压采样、RAM改阈值、灯效和Flash保存未实现。没有烧录或连接硬件。

## 构建结果

使用本机STM32CubeMX 6.14.1、FW_G4 V1.6.3生成工程，ST bundle GNU Arm GCC 14.3.1、CMake 4.3.1和Ninja构建Debug。

| 工程 | 编译链接 | Flash占用 | RAM链接分配 | ELF |

| 叶片 | 通过 | 31,136 B / 128 KiB | 13,984 B / 128 KiB | `Code/Fan Blade/build/Debug/Fan_Blade.elf` |
| 中心 | 通过 | 24,760 B / 128 KiB | 10,256 B / 128 KiB | `Code/Center Controller/build/Debug/Center_Controller.elf` |

同目录生成HEX、BIN、MAP及compile_commands.json。RAM数字包含链接脚本的堆/栈预留，不是实测栈峰值。栈预留为4 KiB，IOC与链接脚本同步；没有Flash参数分区。Release预设已经配置，本次验收构建为Debug。

应用/共享模块按`-Wall -Wextra -Wpedantic -Werror`编译，最终构建日志无warning/error。编译器在沙箱内出现Windows CreateProcess/DLL relocation问题，改为获准的正常本机环境执行同一Build任务后通过；没有执行Flash任务。

## 验证结果

- 两份IOC重新通过本次网表、ST引脚数据库、时钟计算和DMA唯一性静态交叉检查。USART2 RX为PA15；中心晶振16 MHz；主频160 MHz；FDCAN 40 MHz/1 Mbps；ADC40 MHz/10 kHz触发；SPI5 MHz。
- 新业务代码分离到`App`与`Common`，CubeMX的`main.c`在USER CODE区调用应用入口。参考工程72个源代码/配置/工具文件的SHA256与执行前一致。
- 四个C回归程序通过：协议/快照/C620解析及中心2048个标准ID发送白名单；参考击打测试及十环新映射；实际ADC采样模块的模拟DMA/IRQ/恢复路径；实际MCP2515驱动的模拟寄存器/SPI收发与故障路径。
- 四项Python测试通过：串口分块、CRC错误重同步、超时、非法长度、压力/状态/电机字段解码。
- VS Code JSON与默认任务检查通过：默认Build只构建；Flash和F5调试入口明确要求目标ST-LINK序列号。ST-LINK连接与烧录能力未经实机验证。
- 中心两类CAN发送驱动均限制只发送叶片命令`0x500`；不包含C620驱动功能。灯输出保持关闭，Flash保存接口返回不可用。

日志与参考哈希：`tmp/bringup-20261106/build-leaf.log`、`build-center.log`、`tests.log`、`reference-hashes.json`。可重复运行`Code/tools/firmware.ps1 -Project Leaf/Center -Action Build`与`Code/tests/run_tests.ps1`。
