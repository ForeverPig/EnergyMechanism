## 1. 已确认范围

- 中心控制板位于支架上，STM32控制3508电机并与五块叶片通信；ESP32负责蓝牙与控制端通信。
- CAN1由C620电调（预计采用）与1号叶片共用；CAN2～5分别接2～5号叶片。电调ID按实际默认设置核实，不提前认定为1。
- 电机侧皮带轮与叶片侧传动比40/110，叶片转速较慢。
- 本系统做自由训练和击打检测测试，不做7分钟比赛模拟，不提供独立电机调试模式。
- 上位机选择小符/大符、红/蓝，支持启动、停止、连续训练及连续训练间隔设置。
- 成功后只显示一句增益结果，不执行45秒或30～60秒增益保持计时；连续训练成功后等待设定间隔，重开同样的符。
- 连续模式中，20秒仍未成功也在设定间隔后自动重开同类型、同颜色的符。
- 进入击打检测测试先停转；任一叶片失联，停止本轮并停转。
- 蓝牙断开不改变正在运行的流程，包括已经启用的连续训练。
- 多控制端是期望能力，前提是实现方便、运行稳定；各端能看到当前状态并操作，允许设置操作时间死区。
- 每次训练自动记录成绩，可主动查看历史；Windows与微信不共享历史。存储方式暂定以临时存储为方向，本期记录需求。
- 日常显示机关转速、电压、连接状态等；测试页显示指定叶片十路采样值、约20Hz曲线及击打记录。
- 不做CSV导出，不抓取击打前后的高速波形；叶片内部保留高速ADC检测。
- Windows电脑程序、跨Android/iOS的微信小程序本期只写需求；优先完成硬件基础调试。无需网站、云服务或账号系统。
- 灯效先定义接口，灯条/灯板颗数、分组、串接顺序与走线不预设。
- `Code/Test_EnergyMechanism`作为已验证检测逻辑参考，不继续开发；新叶片程序放`Code/Fan Blade`，中心程序放`Code/Center Controller`。沿用CubeMX、CMake、VS Code/ST-LINK的开发与烧录路线。
- 后续带屏STM32控制小板不属于本期，协议可预留控制端入口。

## 2. 已核对的硬件与工程差异

### 2.1 中心控制板

| 功能 | 网表连接 | 大纲约束 |
| --- | --- | --- |
| MCU | STM32G474CBT6，U7 | 按实际型号生成工程与链接布局 |
| 主晶振 | X1，16MHz | 现有Center Controller.ioc为32MHz，需修正时钟树 |
| CAN1 | PA11 RX、PA12 TX，FDCAN1 | 电调和1号叶片共享；报文ID与带宽需共同规划 |
| CAN2 | PB5 RX、PB6 TX，FDCAN2 | 2号叶片 |
| CAN3 | PB3 RX、PA15 TX，FDCAN3 | 3号叶片 |
| CAN4 | U6 MCP2515，SPI2：PB13/14/15，CS=PA8，INT=PB12，RESET=PB7 | 4号叶片；MCP2515晶振16MHz |
| CAN5 | U8 MCP2515，SPI1：PA5/6/7，CS=PB0，INT=PB11，RESET=PB1 | 5号叶片；MCP2515晶振16MHz |
| STM32至ESP32 | PA9 TX→ESP GPIO5 RX；PA10 RX←ESP GPIO4 TX | USART1双向帧协议 |
| 红蓝辅助输出 | PA4=R_G、PA3=B_G | 保留硬件驱动接口，实际灯用途待确认 |
| Type-C数据 | 经保护和串联电阻到ESP32 GPIO18/19 | 接的是ESP32 USB Serial/JTAG，不是STM32 USB |

CAN4/5必须采用MCP2515支持的经典CAN帧。CAN1按C620要求使用1Mbps经典CAN；建议五路统一1Mbps以复用叶片固件，但其余总线速率须随调试验证。不能将现有ioc中约3.54Mbps的计算值直接沿用。

### 2.2 叶片控制板

| 功能 | 网表连接 | 大纲约束 |
| --- | --- | --- |
| MCU/晶振 | STM32G474CBT6，32MHz | 压力检测定时以已验证工程为参考 |
| 压力输入 | PA0～PA7、PB0、PB1，共10路 | 保留每路10kHz的检测目标 |
| CAN | PB12 RX、PB13 TX，FDCAN2 | 不因连接中心CAN1就将叶片外设改成FDCAN1 |
| 本地串口 | PA15 RX、PB3 TX，USART2 | Fan Blade.ioc的RX=PB4与网表不符，应改为PA15 |
| 灯通道 | DOUT1～6依次对应PA11、PA10、PA9、PA8、PB15、PB14 | 仅定义物理输出资源，逻辑灯区映射待组装 |
| 灯使能 | PA12=PWM_OE，经Q3控制74AHCT541 | 需根据完整电平路径验证使能逻辑 |
| 电压采样 | PB2=ADC2_IN12，PB11=ADC2_IN14 | 分别采集5V分压和VIN分压 |

新板PA11/PA12已用于灯输出/使能，不能继续启用测试板的USB CDC。调试数据经叶片CAN→中心STM32→ESP32→上位机传递，也可保留叶片USART2本地调试能力。SWD引脚仍可用于烧录。

SWD连接器线序也有差异：测试板CN2的1～4脚为3.3V/GND/SWCLK/SWDIO；新叶片及中心板CN2为3.3V/SWDIO/SWCLK/GND。沿用ST-LINK烧录方式时，应按新网表接线，不能把旧四芯线顺序直接照搬。

现有Fan Blade.ioc只是起点，CAN位时序、串口、灯DMA与电压采集需逐项核对。中心工程还需补全MCP2515中断/复位、辅助输出等配置。在实际修改CubeMX前，先列出本次外设、引脚、时钟、DMA、ADC Rank的变更清单。

### 2.3 TEST.enet与新板的环号对比

以用户确认的测试板实际薄膜接线及当前检测程序映射为依据。两板传感器接口的1～11号脚信号次序一致，6号脚为3.3V；新接口另有机械焊盘/接地定义，线束仍需核对插接方向。

| 薄膜信号 | 已验证环号 | 测试板MCU | 新板MCU |
| --- | --- | --- | --- |
| IN1 | 6 | PA0 | PA0 |
| IN2 | 7 | PA1 | PA1 |
| IN3 | 8 | PA2 | PA2 |
| IN4 | 9 | PA3 | PA3 |
| IN5 | 10 | PA4 | PA4 |
| IN6 | 5 | PA5 | PA5 |
| IN7 | 4 | PA6 | PA6 |
| IN8 | 3 | PA7 | PA7 |
| IN9 | 2 | PB0 | PB1 |
| IN10 | 1 | PB1 | PB0 |

因此，保持薄膜原接线时，按PA0～PA7、PB0、PB1采样顺序，新程序的环号表应为：

```c
{ 6, 7, 8, 9, 10, 5, 4, 3, 1, 2 }
```

测试程序原表为`{6,7,8,9,10,5,4,3,2,1}`。只调整新程序的软件映射即可，不需要先改线。逐环实测是最终验收；网表比较不能替代实物验证。

## 3. 总体职责与数据流（建议架构）

```text
Windows程序 / 微信小程序（可有多个连接端）
                    ⇅ BLE
             ESP32-C3：连接与转发
                    ⇅ UART
中心STM32：训练状态、命令裁决、成绩结果、电机控制
  ├─CAN1─C620＋叶片1
  ├─CAN2─叶片2
  ├─CAN3─叶片3
  ├─CAN4─叶片4（中心侧MCP2515）
  └─CAN5─叶片5（中心侧MCP2515）

叶片：本地ADC/击打检测/电压采样/灯效执行
```

中心STM32作为运行状态的唯一权威：是否开符成功、当前目标、计时、有效环数、连续训练等均由中心判定。ESP32和界面不各自运行一份独立规则状态机。蓝牙断开、界面卡顿不能改变电机与开符流程。

叶片上报所有已通过本地检测算法的击打事件，包括当前非目标靶的事件；中心判断有效、错靶、屏蔽环或重复。否则中心无法判断打错靶。

### 4.1 模块

| `hit_detector` | 参考现有中值滤波、基线、起始/峰值/上升量/脉宽、释放、分组和锁定算法 |
| `sensor_mapping` | 物理输入、ADC序列与环号转换，独立于检测算法 |

| `blade_link` | CAN命令、事件、状态、参数应答、分片和重组 |

### 4.2 检测和观测

- 按已验证工程10路、每路10kHz逻辑组织，参考32帧循环DMA及半满/全满处理，保留采样来源对齐检查。
- 当前源码参数为最大脉宽600点，即60ms；旧README写400点/40ms，不能照旧README覆盖实际可用代码。
- 击打事件包含叶片身份、启动代次、事件序号、环数、峰值、采样时间戳和参数版本。
- 上报约20Hz十路`raw/baseline/delta/peak/state`，按订阅启停，不将10kHz全部原始流送蓝牙。
- 事件优先于快照；队列有界、丢失有计数，不让通信阻塞ADC。峰值是ADC计数，不能标为牛顿或帕斯卡。
- 复位、DMA异常和重新校准时明确报告NOT_READY；中心不能误把正在校准的叶片当作可用靶。

### 4.3 电压采集

PB2路径：5V→R45(10k)/R48(10k)分压→U19缓冲→ADC，标称恢复系数2。
PB11路径：VIN→R49(10k)/R51(1k)分压→U19缓冲→ADC，标称恢复系数11。

`Vrail = ADC / 4095 × Vref实际值 × 分压恢复系数 × 校准修正`

建议利用内部参考或实测校准修正VDDA误差。两路额外电压采样不能直接塞入旧四Rank数组：须重新核对ADC2扫描时间、Rank数、DMA步长和10路压力组合顺序，确认不破坏10kHz检测。两路电压的调度方法在CubeMX变更方案中单独说明。

### 4.4 灯效预留

抽象接口覆盖：颜色、亮度、目标图案、流动箭头、单臂完成、大符组进度、整体成功、全灭和切换灭灯。状态命令带版本/序号，重复接收不重启动画。

物理层再实现六路输出、实际灯类型、颗数、逻辑区域到灯珠的映射。现有320颗单链配置只作历史测试，不作为新板最终布局。

灯效定时和传输非阻塞；中心按实际点亮时间安排判定窗口。灯珠组装前使用状态回读/模拟灯效验证接口，不声称通过最终视觉验收。

## 5. 中心STM32程序大纲

### 5.1 运行状态

建议顶层：`IDLE / TRAINING / RESTART_WAIT / HIT_TEST / FAULT`；训练内部再划分首击、补击、换靶灭灯、流程重试等子状态。

- 上电等待通信、叶片就绪和启动命令；是否允许启动取决于所有必需叶片与电机状态。
- `START_SMALL(color)`、`START_BIG(color)`启动自由训练；不实现比赛机会发放。
- 保留规则的2.5秒首击、1秒补击、20秒外层尝试、五组判定和换组至多200ms灭灯。
- 小符五个不同灯臂依次完成；大符五轮双靶，第二靶未中不导致该轮失败，第五轮也保留补击。
- 成功生成成绩及一句增益提示；连续训练按设定间隔重开同类型、同颜色；不等待官方增益保持时间。
- 连续模式下20秒尝试超时，记录失败结果并按同一间隔重开；失联故障不能套用普通失败自动重开。
- 进入测试先停转并结束当前训练流程；停止方式、最大减速度等由硬件调试确定。
- 任一叶片失联终止本轮并停转；重新上线不能悄悄接续中断的一轮。恢复启动策略待确认。
- 蓝牙断开仅更新控制端在线状态，当前训练照常执行。
- 内部规则失败与20秒整次失败分开：前者清本轮开符进度，后者产生整次尝试结果。外层20秒不因内部重试延长作为建议策略，须在规则策略确认后定版。

### 5.2 模块

`can_router`、`mcp2515_driver`、`blade_manager`、`motor_c620`、`speed_controller`、`rune_rules`、`training_session`、`command_dispatcher`、`telemetry`、`settings`、`fault_manager`。

中心以物理CAN端口判定叶片1～5；建议通过启动握手分配逻辑编号并带MCU UID核对，避免要求五块叶片分别编译。具体握手帧在协议阶段确定。

### 5.3 电机控制与速度换算

C620 CAN命令是转矩电流命令，中心需要速度闭环，不能把期望rpm直接塞进控制帧。配置PID、限流、积分限幅、输出斜坡、反馈超时等，参数由实际机构调试确定。

皮带换算（已知）为：

`机关rpm = 电机皮带轮rpm × 40/110`

因此小符机关10rpm，对应电机皮带轮27.5rpm。若3508保留P19减速箱，则C620反馈的转子rpm还要除以内部减速比G：

`机关rpm估算 = 转子rpm / G × 40/110`

`转子目标rpm = 机关目标rpm × 110/40 × G`

P19官方说明内部减速比约19:1；此时小符转子约522.5rpm，仅用于量级核对。实际是否保留减速箱、精确G与安装方向必须在调试时确认，不硬编码近似值。无机关轴编码器时，界面显示的是按电机反馈与传动比估算的机关转速，不能检测皮带打滑。

小符训练匀速π/3 rad/s，大符激活按`a*sin(ωt)+(2.090-a)`运行，参数范围沿用规则参考。训练上电/停止/测试停转与比赛规则的持续旋转属于不同层级。成功等待重开期间的旋转策略尚待确认。

### 5.4 状态与成绩输出

输出模式、颜色、目标mask、命中mask、组进度、当前计时、轮次、连续设置、故障、各叶片就绪/校准状态、电机反馈和各叶片电压。

电压来源必须标明叶片编号和电源轨。中心板网表未见中心STM32直接采电源电压，C620标准反馈也没有电压字段；不能把某叶片VIN称为中心精确母线电压。

成绩由中心生成唯一记录ID，建议用设备/启动代次/训练会话/尝试序号组合，避免重传、多端和重连重复计数。

## 6. ESP32-C3程序大纲

建议以ESP-IDF构建，BLE采用官方支持的栈；具体稳定版本和主机栈选择在实现时固定，不在大纲中锁死SDK版本。

- UART帧接收、校验、队列、中心在线检测与命令应答路由。
- BLE广播、连接、GATT控制写入、状态通知、订阅管理、分片和流控。
- 新端连接后读取中心完整快照，随后按状态版本接收更新，不能只等待下一次击打事件。
- 向所有订阅端同步中心确认后的状态；控制请求保留来源和请求ID。
- 把命中/结果/故障与约20Hz压力快照分队列，慢客户端不能拖住中心或其他端。
- 控制端断连后释放该端订阅，但不主动发送停止命令。
- 保留USB串口诊断能力；后续有线入口复用同一命令路由，不另建状态机。
- 本期先验证单端完整链路，再验证两个以上控制端；正式支持数量以实测资源、延迟和稳定性为准，不承诺理论最大连接数。
- 不将完整长期训练历史强制写入ESP Flash；它主要负责传输，暂存/补发范围待记录需求确定。

## 7. 多控制端方案与影响

ESP32-C3软件栈支持配置多个BLE连接，但多连接能力不等于多端命令已被正确协调。

建议由中心按收到的命令串行裁决，每个控制端发显式目标命令，如“设置大符蓝色”，不用含糊的“切换”命令。命令携带请求ID和预期状态版本；成功返回新状态版本，冲突返回当前状态及拒绝原因。

| 问题 | 建议处理 |
| --- | --- |
| 两人同时启动/换色/进入测试 | 中心接受一个状态变更，另一个返回忙或状态已变化，不能两端各显示成功 |
| 有人根据旧界面下令 | 校验预期状态版本，提示刷新后操作 |
| 控制死区 | 中心维护统一截止时间，所有端显示相同剩余时间；死区长度待定 |
| 停止命令落在死区内 | 建议停止优先且绕过普通切换死区，具体策略待确认 |
| 蓝牙丢包/重传 | 请求ID去重，回报最终执行状态；BLE写成功不等于中心执行成功 |
| 多人同时看压力曲线 | 按叶片聚合订阅，限制总遥测量；选择的监测叶片属于各客户端本地视图 |
| 一人改阈值，另一人正观察 | 中心串行执行，回读参数版本并同步到相关端；建议仅测试模式允许修改 |
| 某端临时卡顿 | 有界队列、丢弃过时快照，保留最新状态和重要事件；必要时重取快照 |

后果是BLE内存和无线带宽增加，命令冲突处理增多；如果没有中心仲裁，容易出现互相覆盖和界面状态分叉。建议先测2端，再决定是否扩展3端及以上。此为验证顺序建议，不是用户已经指定的并发上限。

## 8. 参数修改、校准和Flash保存的可行性

当前硬件可完成，不需要新增EEPROM。此三项的本期纳入范围待用户确认。

#### 存到哪里

建议每块叶片把自身检测阈值存入本片STM32G474CBT6的内部Flash预留参数页；运行时在RAM中使用一份副本，上电从Flash恢复。不是把参数只存在手机或ESP32中，因此更换控制端不会丢掉该叶片的配置。中心若需要保存自身配置，再使用中心STM32自己的参数区。

G474CB的B容量档为128KB Flash。预留参数区会占用部分程序空间，由链接脚本明确排除，不能随便向“看起来空闲”的地址写数据。建议规划两个独立擦除页作为A/B记录区；具体地址和占用容量待读取实际bank/选项字节并核对页布局后固定。此处只是在规划，不表示已改链接脚本或实际Flash。

#### 擦写寿命

ST数据手册DS12288 Rev6表48给出的Flash耐久度为至少10k次擦写循环，条件为环境温度-40～105℃。寿命针对被反复擦写的存储单元/页，不是整颗芯片所有读写共用一个10000次额度；读取、RAM修改和正常运行不会因而消耗页擦写次数。

数量级示例：若最简单实现每次保存都擦同一页，每天保存10次，则10000次约对应1000天（2.7年）；这只是擦写次数预算，不是整机寿命承诺。对仅在调参完成时手动保存的使用方式，内部Flash通常适合。不能每次击打、每帧20Hz曲线或每次滑动阈值控件都写Flash。

建议参数未变化时不写；后续可采用页内追加多条参数记录，页满才整理换页，以减少擦除频次。无论简单双份还是追加日志，都要在另一页保有有效版本后才回收旧页。长期训练历史与高频采样不存到这里。

| 能力 | 做法 | 复杂度 |
| --- | --- | --- |
| 远程读/改阈值 | 命令经BLE→ESP→中心→指定叶片；校验范围后原子替换RAM配置并回读 | 较低至中等，现有检测配置结构可参考 |
| 重新校准 | 测试模式下停止计分，重新运行静态基线建立，报告进行中/不稳定/完成 | 较低，现有算法已经具备基础 |
| 掉电保存 | 参数写STM32内部Flash预留区，上电校验加载，异常回退默认值 | 中等，主要工作在存储可靠性和烧录兼容 |

建议明确区分“应用”和“保存”：应用只改变RAM；用户点击保存才写Flash，不跟随滑条每次变化擦写。

建议保存结构含魔数、版本、长度、序号、CRC及提交标志，采用不同擦除页中的双份记录；先写新记录并校验，最后提交，旧记录在新记录有效前保留。具体页大小、bank/选项字节和地址须按STM32G474CBT6核实，不能照搬512KB型号的例程地址。

链接脚本为参数区留空间，构建检查固件不越界；升级使用整片擦除时会丢参数，必须在烧录流程中区分“保留参数升级”和“恢复出厂”。不承诺普通烧录天然保留配置。

仅在停转的测试模式执行保存，保存期间暂停检测和计分、向中心声明维护中，避免Flash擦写影响实时采样；完成后恢复并按需要重新校准。维护超时仍须报故障，不能通过无限屏蔽心跳来掩盖叶片失联。

标定阈值适合持久化；每次上电随环境建立的瞬时基线不建议直接作为固定阈值永久复用。参数保存与历史成绩保存是两套独立需求。

## 9. 协议大纲：先确定语义，硬件调试后冻结字节布局

| 消息组 | 主要内容 |
| --- | --- |
| 发现/握手 | 设备UID、角色、物理端口、固件/硬件/协议版本、功能能力 |
| 运行命令 | 开小符/大符、颜色、停止、连续开关、间隔、进出测试 |
| 执行应答 | 请求ID、接受/执行/失败状态、错误原因、最新状态版本 |
| 全量状态 | 当前训练状态、目标、进度、计时、连续设置、故障 |
| 击打事件 | 叶片、环数、峰值、采样时间、事件序号、参数版本 |
| 训练结果 | 尝试ID、成功/失败/中断、耗时、命中数、平均环数、增益摘要 |
| 遥测 | 转速、电流、温度、五片电压、就绪状态、丢帧/错误计数 |
| 压力订阅 | 订阅指定叶片、刷新率、十路快照、取消订阅 |
| 参数/校准 | 读取、应用、保存、恢复默认、重新校准及进度，范围待确认 |

CAN1协议避开电调控制`0x200/0x1FF`和反馈`0x201～0x208`；叶片精确ID分配不在本期大纲中擅自固定。经典CAN单帧最多8字节，快照等多帧消息需快照序号/分片号/完整性判断，不能拼接两个采样时刻。

UART和BLE规定长度、版本、类型、来源、请求/事件序号、校验和分片边界。不要让协议依赖单次UART接收或BLE通知恰好是一整帧。约20Hz×10路是观测流量，CAN1还有电调反馈，必须实测总线占用、队列峰值及MCP2515接收压力。

叶片时间戳与中心时间属于不同时钟域，应设计同步/偏移估计和重启代次，不能直接比较各板HAL_GetTick。跨板事件排序、判定窗口和换靶执行时间需统一，避免通信延迟改变2.5秒/1秒边界。

## 10. Windows与微信小程序需求

### 10.1 首页/日常操作

- 扫描、连接、重连与设备识别；连接后立即显示当前运行状态。
- 小符/大符与红/蓝选择，明确启动/停止，连续开关和可设置间隔。
- 五叶片状态示意、当前目标、组进度、最近命中环数、成功/失败反馈。
- 机关转速（目标/估算实测）、各叶片VIN/5V、电机温度等已实现遥测；数据过期显示离线，不继续伪装为实时值。
- 成功后一句增益提示，不显示增益倒计时、不等增益结束再开。
- 多端操作显示中心确认后的统一状态、忙/冲突提示与操作死区。

### 10.2 击打检测测试页

- 进入时请求中心停转，确认进入测试后显示可操作状态。
- 选择1～5号叶片，显示十环示意和10路`raw/baseline/delta/peak/state`、校准状态、约20Hz曲线。
- 命中高亮、峰值、环数、事件时间及记录；环上亮点只表示环号，不能伪造命中角度。
- 参数读写、校准和保存按第8节确定范围提供；所有执行结果必须回读目标叶片。
- 无CSV导出，无全速波形捕获，不设独立电机调试页。

### 10.3 训练成绩与进步观察

已确认每次训练自动开始记录，主动查看历史，各平台不共享。本期先规定数据含义和界面需求，临时存储的寿命（页面关闭/程序退出/设备断电）仍需后续明确。

建议记录：日期/时间、符类型、颜色、尝试结果、耗时、有效命中数、环数分布、平均环数、错靶事件数、首击超时次数、参数/规则版本和终止原因。连续训练下每次重开生成新的尝试记录，并可汇总到同一会话。

建议展示累计尝试数、成功次数、成功率、成功用时趋势、平均环数趋势，以及分小符/大符统计。停止/失联中断与正常20秒失败应分别统计，不混为普通训练失败。

“成功率”按开符尝试统计；硬件看不到完全打空的弹丸，不能直接计算真实射击命中率。不同有效环限制、阈值和速度设置的成绩需带版本/条件，避免把条件变化误判为水平进步。

晚加入或断线期间没有收到的历史，不能仅靠状态同步自动补齐；是否保留中心短期结果缓存/重连补发属于待定需求。当前状态同步是必须项，跨平台长期历史同步不做。

## 11. 本期实施与验收顺序（大纲，不代表本次已经开始编码）

1. **建立两套新STM32工程**：按网表核对时钟、UART、CAN、SPI、ADC、DMA、灯输出及内存；建立独立构建烧录入口，测试参考工程不改动。
2. **单叶片检测验证**：按新映射逐环击打，对比原测试逻辑；核对10kHz采样、校准、锁定、峰值与异常恢复，加入两路电压时复测采样时序。
3. **中心五路CAN联调**：先各路心跳/回读，再五片同固件编号、事件和快照；重点验证MCP2515溢出及CAN1电调共线。
4. **电机基础验证**：确认电调ID、减速箱和皮带方向，校对目标/反馈速度及失联停转；这是内部调试步骤，不新增面向用户的电机调试模式。
5. **ESP串口与BLE链路**：单端命令应答、状态订阅、压力订阅、重连；再测多端冲突、死区、慢端和蓝牙全断开不影响训练。
6. **自由训练状态机**：小/大符、颜色、连续重开、单句增益、成绩事件；灯具未完成时用状态回读验证接口，组装后补灯效实测。
7. **参数功能（范围待确认）**：测试模式应用、校准、保存/重启恢复、保存中掉电和烧录保留策略。
8. **冻结首版协议与上位机需求**：用调试结果修正文档；Windows和微信正式界面下一阶段实现。

关键验收：任一叶片断线停轮停转；控制端全部断开仍按原设置运行；20Hz观测不降低击打检测；首击/补击/总时限不串用；十次大符命中可正确统计；多端不会因重传重复开符或重复记成绩；旧状态命令不会悄悄覆盖新状态。

## 13. 后续Type-C带屏控制板的接口边界

本期不实现，但现有网表必须明确：Type-C接ESP32-C3固定功能USB Serial/JTAG设备，不能把它当作中心STM32的直接UART或USB口。

后续若仍用该Type-C接带屏STM32板，带屏板需要合适的USB Host硬件/软件与CDC主机驱动，核对连接器角色与VBUS供电；两个USB设备端直接相连不会自动成为串口。数据路径仍是带屏板→ESP32→UART→中心STM32。

如将来要绕过ESP32直接有线控制中心，需要另行规划硬件通道。本期仅在命令模型中保留控制端来源，不擅自改板或承诺任意STM32小板即插即用。
