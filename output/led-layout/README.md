# 300 mm 能量机关灯板布局原型

新增离线程序 [editor.html](editor.html)，可沿固定半径拖动八向对称灯组、按环调整大灯数量、联动电容，并保存项目／导出经过封装中心补偿的嘉立创坐标。编辑器当前默认为308颗5050＋24颗小灯；最外圈的8颗小灯已原位转换为5050，最外圈共64颗大灯，总数仍332颗。旧项目会自动转换并保留手动调角。操作和封装预设说明见 [编辑器使用说明.md](编辑器使用说明.md)。下文的原始默认布局和预览文件作为旧版参考保留，当前布局使用编辑器导出。

双击 `preview.html`，浏览器即可离线使用。默认 **300颗5050 + 32颗同半径十字2020补光，合计332颗LED**，另配332颗 **100nF／0402电容**和16个安装孔。本轮删除7环（R52.5mm）的8颗小灯与配对电容，LED／电容位号连续顺延；保留其余元件角度和LED中心、主灯电容位置。小灯电容的移位以移位前中心为基准，由局部+X 1.5mm修正为局部−X 1.5mm，不绕LED中心镜像，实际比上一版反向移动3mm。

5050局部上边朝外，小灯局部上边朝内；所有电容的角度仍为对应LED角度+180°，本轮不再旋转。圆心不放灯，小灯仅在十字区域、与5050灯环同半径，十环模式下小灯全部关闭。编号从内向外逐圈逆时针；R82.5／97.5mm从3点钟下侧小灯进入，对应LED76→LED77、LED116→LED117；R52.5mm现为20颗主灯，从3点钟开始。控制器接LED1 DIN，之后按LEDk DOUT→LED(k+1) DIN连接到LED332。预览连线表示预定顺序，尚未生成PCB铜线或网络。

SCREW1～SCREW16为钻孔Ø3mm、焊盘外径Ø5.8mm的带铜安装孔。每组在y=±x的45°、135°、225°、315°方向，依次放在R30mm（9-8环交界，SCREW1～4）、R60mm（7-6环交界，SCREW5～8）、新增R90mm（5-4环交界，SCREW9～12）、R120mm（3-2环交界，原SCREW9～12顺延为SCREW13～16）。安装孔外圆与元件假定包络最小间距约1.262mm。

本轮修改前的快照在`placement-before-ring7-removal-cap-reverse.json`，删除／顺延／安装孔新增对照在`designator-renumber.csv`，全部32颗小灯与配对电容位号在`small-led-designators.csv`。当前本体和假定包络相交均为0，包络最小间距约0.30mm。CSV导入不会删除、改号或创建元件，先按对照表处理原7环小灯及电容，再顺延位号并添加4个安装孔。

这是一份尺寸与灯效规划原型，尚不是可投产 PCB。未修改 STM32 固件或 CubeMX 配置。

- 印刷页 104（PDF 第 105 页）图 5-22：可激活标识的三条圆带外径 70、150、270 mm，宽度 20 mm。因此按半径区间 [15,35]、[55,75]、[115,135] 建模。
- 四条辐条按外端宽 35 mm、轴向长 100 mm、单侧相对轴线 7° 重建。内端轴向坐标为 50 mm，内端宽约 10.44 mm。辐条在外缘裁剪到半径 150 mm。原图是示意图，35 mm 与圆弧交点等细节存在图示近似；这是同时采用这些尺寸的参数模型，不是官方矢量 CAD。
- 用户图 3 电阻膜：外形半径 155 mm，1 环外边界标 R150.50，其他环边界 R135、120、105、90、75、60、45、30、15。预览保留 R150.5，不把整个计分区域等比例缩放到 310 mm。与灯板同心时，膜外形比板外缘伸出 5 mm；膜的 1 环有效外边界比规则外边界大 0.5 mm，需核对供应商实际尺寸及公差。

## 当前推荐：300～399颗、以5050为主

数量约束按主灯和补光灯**合计**理解。默认332颗包含300颗5050（约90%）和32颗2020。小灯仅位于十字部分，必须采用现有灯环的中心半径，通过改变角度在同一圆周上补点。

每个15 mm计分环带的中心线放一圈5050，半径从中心向外为7.5、22.5、37.5、52.5、67.5、82.5、97.5、112.5、127.5、142.5 mm。对应灯数为4、8、16、20、28、32、40、44、52、56，总计300，圆心不再放灯。四轴均有主灯。除最内圈以外，圆周间距约14.7～17.7 mm。

补光位置：

| 用途 | 灯环半径r / 相对十字轴线的横向偏移u（mm） | 数量 |
| --- | --- | ---: |
| 中部十字 | r=82.5，u=±6.5 | 8 |
| 中部十字 | r=97.5，u=±8 | 8 |
| 外侧十字 | r=112.5，u=±9.5 | 8 |
| 外端十字 | r=142.5，u=±8 | 8 |
| 合计 | 每个选定半径，在四条十字臂上各补左右两颗；环模式全部关闭 | 32 |

用极坐标保持半径严格一致：对于第k条十字轴线（k=0..3），`theta=k*pi/2 ± asin(u/r)`，再用`x=r*cos(theta)`、`y=r*sin(theta)`生成小灯坐标。不要直接使用`(r,u)`作平面坐标，后者的实际半径是`sqrt(r*r+u*u)`。小灯均位于十字内、三条标靶圆带之外，也没有与既有轴线上5050灯位重合。

默认小灯按2.2 mm方形本体保守表示2020；这是几何包络，不是对某个料号真实尺寸的承诺，具体封装宽高、焊盘、发光面高度要以采购料号的数据手册为准。主灯按5 mm方形表示5050。

当前332颗方案：LED最小中心距约6.505mm；加入332颗0402电容和16个安装孔后，整体本体重叠为0、最小边缘间隙约0.85mm。默认所有LED旋转后的四个本体角点均在所属15mm计分环内和D300板内。矩形采用分离轴与边段距离检查，安装孔按圆形外圆与旋转矩形的距离检查。

电容100nF，0402按1.0×0.5mm本体表示，长边与LED局部X轴平行。5050电容位置不变，局部中心(-3.2,+3.6)mm。剩余32颗小灯电容在移位前中心上加`rotate(-1.5,0,small_LED_current_angle)`；相对上一版错误右移后的中心，应加`rotate(-3,0,small_LED_current_angle)`。不镜像、不再次旋转。当前小灯电容在LED局部坐标下为(+0.3,-2.2)mm，精确参考值见`pcb-positions.json`的`report.smallEdits`。

规划检查另用LED每侧0.3mm余量、0402电容1.6×1.0mm包络，均为可核对的**假设**，没有读取实际EDA库焊盘。删除7环小灯并修正其余小灯电容移位后，当前假定包络相交为0、最小间距约0.30mm。安装孔外圆无包络相交。本体与包络报告均在`pcb-positions.json`；真实焊盘仍需在实际PCB中核对。

用户给定5050的0°方位为：左上1=5V、左下2=DOUT、右上4=DIN、右下3=GND。本次摆放按此方位生成；电容电气上必须跨接**VDD与GND**。小灯不能直接照搬5050脚号：例如Worldsemi WS2812B-2020-V6手册第2页为1=DO、2=GND、3=DI、4=VDD。小灯的0°库方向、供电脚在本模型左上角的相对位置需要单独核对，当前小灯电容坐标仍是按用户给定方位的预排，不是已确认的小灯库封装。资料：[2020-V6制造商数据手册](https://datasheet.lcsc.com/datasheet/pdf/a29e59ba4bc7e47e236b4d50b6c26345.pdf?productCode=C52917434)。

## 332颗单线级联的刷新时间

按800kbit/s、24bit/颗计算，发送332颗的数据需要9.96ms。使用320μs复位低电平，一帧发送加复位为10.28ms，约97.3帧/秒的理想串行吞吐上限；未计软件开销、器件转发传播时间或裕量。60Hz刷新足够；若要求至少100Hz全帧更新，应考虑两条或更多数据链。2020-V6手册列出800kbit/s、24bit GRB及≥280μs复位。全部灯按串行DOUT→下一颗DIN级联，与控制器共地；信号自动整形不等于电源足够。

应使用定时器PWM＋DMA或等效外设发送，避免整帧10ms期间软件忙等关闭中断。5V/GND按具体料号电流预算，采用适当的供电干线/铺铜和多点供电；每灯100nF负责局部去耦，不代替分区储能或供电干线。此轮未修改固件；上次检查STM32工程的`app_config.h`为4+10+16=30颗、800kHz、256复位槽（320μs），后续332颗集成需扩大缓冲并重建环号/链序映射。

标靶模式点亮148颗：116颗5050和全部32颗2020。十环模式只控制300颗5050，全部补光灯关闭。导出数据保留小灯的几何环号，用于定位；小灯的环号不用于环模式开关。主灯和小灯均独立寻址。

这是单圈5050主灯加十字细节补光的数量受限方案。圆带由5050采样位置和扩散层呈现，当前单排灯不保证20 mm宽度内的均匀面光；小灯只补辐条。需要光学小样验证图案连续性、亮度及识别效果。大小灯应分别做实测PWM亮度校正。

## 此前的高密度对照方案

采用同心圆排布，每个 15 mm 环带放两圈灯。第 k 个从中心向外的环带（k=0..9）灯珠半径：

```
r = 15*k + 3.75 mm
r = 15*k + 11.25 mm
```

中心另放一颗。每圈颗数用下式向上取为 4 的倍数，确保四个轴向都有灯：

```
N = max(4, 4 * ceil(2*pi*r / pitch / 4))
theta = 2*pi*j/N, j=0..N-1
x = r*cos(theta)
y = r*sin(theta)
```

这里的 pitch 是圆周目标间距上限；实际弦长略小，中心区域尤其不能简单视为 8 mm 等间距。选择每环两圈、2 mm 本体、目标间距8 mm时，总数1217，标靶点亮620。各环灯数由外向内为228、204、180、156、132、108、88、64、40、17。最小中心距为中心区域的3.75 mm。

其他方案：同样 8 mm 目标间距，每环一圈 617 颗，标靶点亮 240；三角点阵 1261 颗，标靶点亮 602。单圈方案径向只有一排灯，更适合点状圈线。双圈更有利于填满 15 mm 环带及标靶的 20 mm 圆带，但成本、功耗和数据量都会增加。这些数量是本模型输出，不是比赛规则要求的数量。

这些高密度方案保留用来对比离散程度，均不符合本次低于400颗的数量约束。当前默认为332颗同半径十字补光方案；对照方案未应用本次旋转与中心删除。

## 程序分层

1. `layout.js`：物理坐标、环号、标靶几何判断、按圈逆时针混合编号、导出；不依赖画布或网页。
   `pcb-layout.js`：旋转矩形检查、100nF／0402电容配对及局部偏移规划，供Node及浏览器共同使用。
2. `preview.js`：显示与操作，将每颗灯的物理位置映射到图上；理想轮廓与灯珠中心的判定使用同一组尺寸。
3. 当前单链预定顺序为LED1→LED332，几何ID为位号减一。PCB按编号连接DOUT→下一颗DIN，布线后核对实际网络；如果实际链顺序有改动，需要同步重排固件映射。当前坐标与编号不等于已完成PCB布线。
4. 固件：按 `ring` 批量点亮计分环；按 `target` 点亮可激活标识；灯效与击打检测通道单独映射。

示意逻辑：

```c
for (unsigned i = 0; i < LED_LAYOUT_COUNT; ++i) {
    bool on = (mode == TARGET_MODE)
        ? led_layout[i].target
        : (!led_layout[i].small_package && ring_enabled[led_layout[i].ring]); // 数组有11项，使用1..10
    set_led(i, on ? color : off);
}
```

`led-layout.h` 保存百分之一毫米的整数坐标和掩码，适合后续固件处理。只有导出、没有集成入现有固件。若采用逐灯寻址灯珠，可以用多条数据链；若采用普通 LED，也须用矩阵或足够多的恒流驱动通道实现所需像素控制。整环共用一个开关的十路驱动，无法同时表现跨环辐条和圆带。

### 分组与两种固定图案

若采用普通单色LED分组驱动，可将主灯按环号及标靶归属分组，十字补光灯另成一个独立组。环模式只打开对应主灯组；标靶模式打开主灯中的标靶部分和十字补光组。

共享分组表保留0..15的计分环 / 标靶交集编号，新增16号`spoke-only:T`用于全部十字小灯。当前单圈300颗5050只占15个非空组（8环主灯全部位于标靶外），加小灯共16个非空组。C表声明17个编号槽，包含未使用的8环标靶内组；编号槽数不是实际非空组数。导出`groupKey`的T代表标靶内，B代表其余部分。

这是组合控制所需的逻辑组数，物理恒流驱动支路数量还取决于电压、电流与灯珠串并联方式，不能把整组所有裸灯珠直接无均流并联。该方式适合普通单色 LED，能减少控制复杂度；逐灯寻址适合需要动画、任意颜色和后续自定义图案的方案。

供电预算按选用灯珠的实际通道电流、同时亮灯数与限亮设置计算。若所选协议为 800 kbit/s、24 bit/颗，则 1217 颗一条链仅数据部分为 36.51 ms；这是条件计算，不含复位时间，也不代表任何具体型号规格。多链能缩短刷新时间；电源仍需按分区电流规划，不能让大电流沿灯珠逐颗通过。

## 电阻膜与光学

- 先确认电阻膜及承力 / 保护层的透光率和导电线路遮挡。可以做一个包含两条相邻环带及一段标靶辐条的小样，测试亮度、图案边界、击打可靠性和相邻环串光。
- 从背面到正面通常需规划：灯板、混光间距 / 扩散层、透光承力或保护结构、电阻膜及其必要保护层。最终顺序和承力方式以膜供应商要求、弹丸冲击及光学实测决定。
- 固定只开十环或只开标靶图形的遮光片会限制另一种显示。连续十环隔光墙也可能把标靶辐条切断，应在小样中同时验证两种图案。
- 不建议仅为了掩盖灯珠稀疏而大幅加大扩散距离，因为宽扩散会把已关闭的相邻环一起照亮。预览光斑是几何示意，并没有模拟真实亮度和散射。
- 环边界、膜有效边缘、尾线、固定孔和安装公差需要共同定位。软件中的同心叠图不能代替供应商机械图与实物定位。

- `led-chain-order.csv`：每灯位号、上次位号、半径、环号、角度、类型、下一颗灯及配对电容。
- `placement-before-ccw-renumber.json`：此前小灯混排编号前的340颗LED／电容坐标。
- `placement-before-ring7-removal-cap-reverse.json`：本轮删除7环小灯、修正电容方向和新增R90安装孔之前的完整快照。
- `placement-before-small-flip-screws.json`：此前小灯／电容旋转、平移及安装孔新增前的完整位置和角度。
- `placement-before-entries-84-124.json`：此前修改R82.5／97.5圈入口前的完整位置和角度。
- `placement-before-capflip-seam.json`：此前电容旋转及R52.5入口修改前的坐标和角度。
- `placement-before-20261002.json`：最初341颗布局的完整LED／电容位置，供精确对照。
- `pcb-positions.json`：完整LED＋电容位置、本体/假定包络检查报告及未核对事项。
- `export_jlceda.cjs`：可调整LED/电容的位号前缀、起始编号和灯板中心偏移。
- `build_preview.py`：从源文件重建离线预览与本次聊天的内嵌预览。
- `export_default.cjs`：重建默认导出；调整其中 config 即可改默认方案。
- `check_preview.cjs`：本环境浏览器与几何验证脚本；运行时需要对应的 Playwright 和 Edge 路径。

```
python build_preview.py
node export_default.cjs
```

灯珠、电容本体按实际旋转角检查；规划包络仍是尺寸假设，没有读取实际EDA库焊盘或运行真实PCB DRC。驱动件、连接器、导线、螺孔和装配公差未规划，不能直接用导出坐标下单。
